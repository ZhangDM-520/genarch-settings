# A profile mirror at the engine's sysctl projection path is accepted, and every later `apply` reports "drift persisted" and exits 1

- **severity:** high
- **category:** bug
- **environment:** Arch Linux guest (QEMU, 2 vCPU), `genarch-settings 0.4.0-1`; a converged copy of the staging tree (`GENARCH_SETTINGS_ROOT=~/ev3`).

## Intent

Add a machine-specific sysctl file to a profile as a mirror — the natural first attempt if you do
not want to translate the file into `sysctl.toml` — and then converge the copy.

## Steps

```sh
cp -a ~/machine/root ~/ev3
P=~/ev3/etc/genarch-settings/profiles/qemu-i440fx
mkdir -p $P/mirror/etc/sysctl.d
printf '# profile-owned sysctl.d file\n' > $P/mirror/etc/sysctl.d/90-genarch-settings.conf

GENARCH_SETTINGS_ROOT=~/ev3 genarch-settings report | grep -E "MIRROR|SUMMARY"
GENARCH_SETTINGS_ROOT=~/ev3 genarch-settings apply --dry-run
GENARCH_SETTINGS_ROOT=~/ev3 genarch-settings apply; echo "exit=$?"
GENARCH_SETTINGS_ROOT=~/ev3 genarch-settings apply; echo "exit=$?"
head -2 ~/ev3/etc/sysctl.d/90-genarch-settings.conf
GENARCH_SETTINGS_ROOT=~/ev3 genarch-settings report | grep -E "MIRROR|SUMMARY"
```

## Expected

`SCOPE.md`: "One path has exactly one owner; that is the rule the whole design exists to enforce."

`AGENTS.md`: "The sysctl projection is an engine-written file and therefore lives in `owned`; a
target that leaves the intent is pruned from the record, so no value keeps a second home."

`DESIGN.md`: "**The manifest owns what the engine writes.** `owned` is prune-eligible (mirrors +
the sysctl projection) ... The projection used to be written but unowned, so emptying `sysctl.toml`
left `/etc/sysctl.d/90-genarch-settings.conf` live and unreported — a second home for every value."

The engine should refuse the second owner (it already refuses `mirror`+`managed` overlap with
`… is declared as both mirror and managed: one path, one owner`).

## Actual

The profile mirror is accepted. `report` counts it as one changing MIRROR target. `apply --dry-run`
plans `OWNED /etc/sysctl.d/90-genarch-settings.conf`. The real `apply` writes the engine's
generated projection to that path (the live file becomes the projection's `# Generated by
genarch-settings …` text, never the mirror's bytes), re-plans, finds the mirror still differs,
prints on stderr

`genarch-settings: drift persisted after apply: 1 change(s), 0 sysctl value(s)`

and exits 1. A second apply does the same; the mirror content never appears. The host can never
converge, and the output never names the two owners. A syscall trace of the failing apply shows
one temp-file write and rename of the path (the projection); nothing writes the mirror's bytes.

## What could not be determined

- Whether the projection path is meant to be reserved (the docs describe the projection's
  ownership but never say that `mirror/etc/sysctl.d/90-genarch-settings.conf` is forbidden).
- Whether a pre-flight validation could detect it from the live path alone; the engine's existing
  `mirror`/`managed` check shows the validation seam exists.
